## 一、项目背景

公司主营芯片设计开发，团队横跨算法、IC 验证、数字前端、模拟设计、SoC 架构、软件开发（Ruby/Java 等）、人事等多个岗位。当前 AI 工具（以 Claude、GPT 为代表）在代码生成、文档理解、算法推理、多模态分析等方面能力已显著跃升，但**不同岗位对 AI 能做什么的认知差异很大**：

- 部分工程师已深度使用，视其为日常生产力工具
- 多数岗位仍停留在"听说过、没试过"
- 非工程岗位（如 HR）对"AI 跟我有什么关系"缺乏具象认知

本项目旨在通过一次**集中、直观、可感知**的演示活动，让全员在较短时间内形成对 AI 当前能力的统一认知；并在本轮新增**多模型对照专项**，用公司实际在用的 datasheet 让芯片技术岗直接"看到 AI 读我手里的料"。

## 二、项目目标

1. **认知对齐**：让各岗位同事在 30 分钟内对"AI 当前能做到什么"形成直观判断
2. **岗位落地**：每个核心岗位至少能看到 1 个与自身工作直接相关的应用场景
3. **降低尝试门槛**：演示结束后，超过一半参与者愿意在下周尝试用 AI 辅助自己的工作
4. **积累共享资产**：演示用到的 Prompt、案例、话术沉淀为公司内部资料，后续可复用、可扩展
5.（新增）**模型选型数据点**：对主流大模型读 datasheet 的实际产出做一次横向可审阅的对比，给团队后续选型提供一手资料

> 不追求目标：**不**覆盖所有高阶能力、**不**做深度培训（培训留给后续 `AI.md` 那套文档）

## 三、受众与岗位映射

| 岗位 | 关注点 | 演示想回答的问题 | 模块 6 是否覆盖 |
|---|---|---|---|
| 算法岗 | 模型、数据 | AI 能帮我写/优化算法吗？能读论文吗？ | ✅ |
| IC 验证 | testbench、覆盖率 | AI 能写 UVM 吗？能读我 RTL 吗？ | ✅ |
| 数字前端 | RTL、综合时序 | AI 写的 Verilog 能综合吗？Lint 过吗？ | ✅ |
| 模拟设计 | SPICE、波形 | AI 能看波形图、帮我调参吗？ | ✅ |
| SoC 架构 | 拓扑、memory map | AI 能帮我做架构 trade-off 吗？ | ✅ |
| Ruby 开发 | Rails、测试 | AI 能帮我写单测、理解老代码吗？ | ✖（模块 3 覆盖） |
| Java 开发 | Spring、企业开发 | AI 能省我多少样板代码？ | ✖（模块 3 覆盖） |
| 人事 HR | 招聘、匹配 | AI 能帮我写 JD、筛简历吗？ | ✖（模块 2 覆盖） |

> 模块 6 的岗位分发仅面向上表 **前 5 个芯片技术岗**，Ruby / Java / HR 三岗在其他模块中单独覆盖，避免在 datasheet 场景里强行硬凑。

## 四、演示内容规划（六大模块）

### 模块 1：AI 核心能力展厅

展示"智能度"本身，不分岗位，给所有人看：

- 自然语言直接生成代码
- 算法思路可视化（以一个经典算法为例，AI 边跑边解释）
- 代码审查 / Bug 定位
- 长文档（如 datasheet）速读与提炼

### 模块 2：岗位应用墙

为上述 8 个岗位各准备 **1 个具体场景案例**，统一格式：

> 情境 → 输入（Prompt）→ AI 输出 → 节省的时间/成本

### 模块 3：AI 编程实操

挑 3~4 个与公司技术栈吻合的实操演示（Verilog、Ruby/Rails、Java/Spring、Python 脚本各一），强调**从需求到可用代码**的完整链路。

### 模块 4：文件整理与工程化

展示 AI 在**非编码场景**的价值：

- 读混乱代码库 → 产出 README / 项目说明
- 按约定批量重组文件目录
- 会议纪要 → 任务卡片
- 老文档归档与索引

### 模块 5：边界与护栏

诚实收尾：

- AI 会在什么地方出错（3 种典型失败模式）
- 如何给 AI 加约束（呼应已有的 `AI.md` 第 4 章 Harness 工程）
- 真实投入产出数据

### 模块 6：【本轮新增】多模型 Datasheet 并行解读与岗位分发

> 本模块是本轮演示的**核心互动**，把 AI 从"工具"升格为"可对比、可选型的决策对象"，并让 5 个芯片技术岗**直接看到 AI 读自家 datasheet 能产出什么**。

**一句话说明**：同一批 datasheet（`ai/ai_jinping/` 下 4 份 PDF）丢给 ≥3 个主流大模型，各自独立解读并产出**对比文档**，按模型名分目录沉淀到 `ai/<模型名>/`；最终在一张 HTML 页面上，按 5 个技术岗 Tab 切换，只露出与该岗位工作直接相关的技术要点。

**为什么要放进来**：模块 1~5 偏"单向展示"，模块 6 是**可复用的资产 + 决策工具**：

- 演示完不会"看完即散"，所有产出都在仓库里可随时复查
- 参会技术岗同事能直接看到"我若平时用 AI 读 datasheet"会是什么体验
- 给后续"公司到底统一用哪个模型"提供一手对比数据

**输入**：`ai/ai_jinping/` 下 4 份 datasheet PDF（A17802 / FI3710 / MLX90514 / REN RAA2P4520）

**产出**：

1. `ai/<模型名>/<芯片>.md` ×（N 模型 × 4 芯片）—— 单模型单芯片解读
2. `ai/<模型名>/_summary.md` × N —— 每个模型对 4 款芯片的横向总结
3. `ai/_cross-model/comparison.md` —— 跨模型对照文档，按 5 岗位视角切片
4. `ai/_cross-model/index.html` —— 面向演示现场的单页 Web 展示，Tab 切换岗位视角

**详细执行方案见第七章**。

## 五、演示形式（待定，需选择）

| 方案 | 描述 | 适用 | 工作量 |
|---|---|---|---|
| A. 集中宣讲 | 一场 45 分钟分享，现场演示 + 问答 | 全员 / 部门会 | 中 |
| B. 自助展台 | 布置成可自由点击的演示站，同事随时来玩 | 灵活、不打扰 | 中高 |
| C. 录屏 + 图文 | 预录视频与配套文档，发内部知识库 | 异步、可反复 | 中 |
| D. 以上组合 | 主讲一场 + 录屏归档 + 文档沉淀 | 效果最佳 | 高 |

> 默认倾向 **D**（效果最扎实）。模块 6 的 HTML 天然适合 B 与 D 的"自助展台 / 异步查阅"形态，能极大降低讲解员负担。

## 六、组织与分工（建议）

- **牵头人**：1 名（统筹演示内容、串讲）
- **内容贡献**：各岗位 1 名代表提供真实场景案例（半小时访谈即可）
- **素材制作**：1~2 人采集 AI 输出、编排案例
- **排练与场控**：演示前 1 次完整过稿
- **模块 6 专员**：1 名（负责执行第七章步骤、整理目录、生成 HTML），可与素材制作复用同一人

> 最小团队 1 人即可独立完成，有协助者则质量更高。

```
│   ├── REN_RAA2P4520.md
```

**命名约定**：

- 模型目录名：小写，用 `-` 分隔，带版本号（例：`claude-opus-4-7`，不要 `Claude Opus 4.7`）
- 芯片 Markdown 文件名：取芯片型号的简短名（见上方示例），**不要**带 `datasheet`、`Datasheet_DST_20251127` 等冗余后缀
- 跨模型对比目录固定为 `_cross-model/`（带下划线前缀，保证它在 `ls` 中排序置顶）

### 7.7 HTML 展示（`_cross-model/index.html`）结构

**交互设计**：

- 顶部：固定 5 个 Tab —— `算法` / `IC 验证` / `数字前端` / `模拟设计` / `SoC 架构`
- 点击 Tab：
  - 左栏：4 款芯片的按钮列表（`A17802` / `FI3710` / `MLX90514` / `REN RAA2P4520`）
  - 右栏：当前"芯片 × 岗位"下，**每个模型一张卡片**并排展示
- 每张卡片：
  - 标题：模型名 + 版本
  - 正文：对应 MD 文件中该岗位章节的摘要
  - 页脚：`查看完整文档 →` 链接（指向 `../<模型名>/<芯片>.md`）
- 底部：跨模型一致性热力图（直接嵌入 `comparison.md` 第二节的表格）

**技术选型**：纯静态单文件 HTML，**不**引入构建工具：

- 样式：内嵌 `<style>`
- 交互：内嵌 `<script>`，用原生 JS 切 Tab
- 数据：Markdown 内容以 JS 数组形式内嵌（由步骤 6 的脚本生成；允许手写）
- 约束：用 Chrome 直接双击打开 `index.html` 必须可用（不依赖任何服务器）

**骨架参考**：

### 7.8 Step-by-step 执行流程

**步骤 1：确认输入**
```
ls ai/ai_jinping/
```
预期看到 4 份 PDF。任何缺漏先补齐再继续。

**步骤 2：选定模型**
参照 7.3 敲定 N 个模型（**≥3**），记录在本章 7.3 的"本次实际选择"清单里（见 7.13）。

**步骤 3：建目录**
```
mkdir -p ai/<模型名>/ ai/_cross-model/
```
每个模型建一个。目录名严格遵守 7.4。

**步骤 4：逐模型、逐芯片解读**
对每个模型，**各自独立会话**（避免互相污染）：

1. 打开该模型的对话入口
2. 按 7.9 的"单芯片解读 Prompt"投喂 1 份 PDF
3. 收下输出 → 保存为 `ai/<模型名>/<芯片>.md`
4. 重复 4 次，直到 4 款芯片都生成
5. 追加一次 7.9 的"单模型汇总 Prompt" → 保存为 `ai/<模型名>/_summary.md`

**步骤 5：跨模型对比**
进入"主持模型"（默认 Claude Opus 4.7），按 7.9 的"跨模型对比 Prompt"：
- 把所有 `ai/<模型名>/*.md` 路径一次性告诉它
- 让它产出 `ai/_cross-model/comparison.md`
- 肉眼抽检一节，修正明显错误

**步骤 6：生成 HTML**
让主持模型按 7.7 骨架生成 `ai/_cross-model/index.html`：

- 从 `comparison.md` 抽取每个"芯片 × 岗位 × 模型"三元组的摘要
- 嵌入 JS 数据数组
- 双击打开验证 5 个 Tab 都能切

**步骤 7：彩排**
演示前 1 天由牵头人走 5 个 Tab，逐个抽查：任何"看不懂 / 明显瞎编"的卡片立刻回到第 4 步重跑该模型对应芯片。

### 7.9 Prompt 模板（三套，**直接可复制**）

**模板 A：单芯片解读（步骤 4 用）**

```
你现在是一个面向芯片设计团队的资深技术文档分析师。
任务：阅读附件 datasheet，输出一份面向 5 个岗位视角的结构化解读。

芯片：{型号}
原文件：ai/ai_jinping/{PDF 文件名}

请严格按以下 Markdown 结构输出（章节号、标题、顺序都不要改）：

{贴 7.5 模板全文}

硬性要求：
- 所有数值必须带单位
- 引用原文时必须给出页码
- 无相关内容时写"本 datasheet 与该岗位无直接关联"，禁止编造
```
